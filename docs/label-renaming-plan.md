# Readable label names: work plan

This plan is written for an agent. It renames every assembler label in Skate
so the source explains itself, and proves that no rename changes a single
output byte.

A large refactor is in progress, so do not start until it has landed. Then
branch from the current `main`, regenerate the baseline (step 0), and rerun
`perfile.ts` for fresh counts. The figures below are a snapshot taken from
`main` at `a596f2e`, and file names may have moved since.

## Why the current names are unreadable

ATOM allows one to eight characters for a global name. A private name is a
`.` followed by one to eight more characters. Both may use letters, digits and
underscores. Matching ignores case. A private label is visible only until the
next global label, and any global label starts a new private scope.

Skate spends that budget badly:

- Every runtime global starts with `SRT` (1,091 labels) and most compiler
  globals start with `SC`. The runtime and compiler assemble into separate
  images, so inside an image those prefixes tell the reader nothing. They
  leave five or six letters for meaning, which produces names like `SRTSVLD`
  and `SCRECPEN`.
- Only 96 private labels exist. Of the 2,451 global code labels, about 1,100
  are only referenced inside the segment of the global before them: loop
  heads, join points, error exits and helpers with a single caller. They can
  all become private.
- No underscores are used anywhere.

## Naming convention

### Global names: `AREA_WHAT`

- Write labels in upper case, as the rest of the source is. Because ATOM
  ignores case, switching to lower-case labels later would be a mechanical
  edit (see "Open decision").
- Drop `SRT` and `SC` completely.
- A global starts with a short area prefix from the table below, then an
  underscore, then a word or two: `STR_COPY`, `STR_NEW`, `LX_NEXT`,
  `PUB_PATCH`.
- When the area is obvious and the name is famous, use the bare word:
  `CONS`, `CAR`, `CDR`, `ERROR`, `PRINT`, `GC`. Use at most about 20 bare
  names in each image, and choose them deliberately.
- Name routines with verbs or operations (`STR_COPY`, `ENV_FIND`). Name
  variables with nouns (`STR_LEN`, `STR_DST`). A trailing `P` marks a moving
  byte cursor (`STR_SRCP`, `STR_DSTP`).
- Spell words out before abbreviating them. `COPY`, `JOIN`, `NEXT`, `FAIL`,
  `DONE`, `MARK`, `LEN`, `PTR`, `IDX`, `TMP`, `ARG`, `CHK` and `NEW` are the
  approved short forms. Do not use vowel-dropped consonant strings such as
  `PCLE` or `CRMK`.
- A name may have at most eight characters. If the name will not fit, choose
  a different word rather than squeezing out more vowels.

### Private names: `.WHAT`

- A global that only its owning segment references becomes private. This
  applies to every loop, join point, error exit and local fall-through
  target.
- A helper routine with a single caller in the segment just before it also
  becomes private (for example, `SRTSSZ` became `.SIZE` inside `STR_NEW`).
  Keep a helper global only when tests or tools look it up, or when merging
  it would create a scope so large that its private names become ambiguous.
  Use judgement here and say why in the batch notes.
- Private names need no area prefix. Prefer plain words: `.LOOP`, `.DONE`,
  `.BAD`, `.GOOD`, `.ALLOC`, `.LEN_READ`.
- After demotion, private names must be unique across the merged scope. When
  two merged routines each have a loop, use `.REF_LOOP` and `.LEN_LOOP`, not
  `.LOOP1` and `.LOOP2`.

### Names shared between images

- `src/compiler/cpm-transport.asm` is assembled into both images. Its names
  take one rename each.
- `src/runtime/values.inc` is generated by
  `tools/compiler-checks/generate-scope-runtime.ts`. It re-exports runtime
  addresses into the compiler. A mirrored equate keeps exactly the runtime
  label's new name, so `SRTCONS` becomes `CONS` in both images.
- Some equates are offsets or have their own compiler-side names (`SRTCLP`,
  `SRTLDA`, `SRTSTA`, `SRTSETS`, `SRTFAL`, `SRTHEP`, `SRTLEN`, `SRTLOW`,
  `SRTPRI`). Give them names that say what they are, such as `RT_LEN` for the
  payload length and `RT_CALLP` for the call-operand offset. Update the
  generator accordingly.

## Tooling (`tools/labels/`)

All of the following scripts run from the worktree root with
`deno run -A tools/labels/<script> $PWD ...`:

| Script | Purpose |
| --- | --- |
| `labels.ts` | Shared scanner: include order, definitions and references, with comments and strings stripped |
| `demote.ts` | Lists globals that can become private. A label qualifies when every reference falls between the surrounding kept globals in the same file. Names that appear in any `tools/` or `tests/` script stay global. |
| `perfile.ts` | For each file, counts the globals kept and demoted, the equates and the existing privates. Use it to size batches. |
| `apply.ts <repo> <maps-dir> [--dry]` | Applies every JSON map in the directory to `.asm` and `.inc` sources (code and upper-case comment mentions), and to `tools/`, `tests/`, `docs/` and `README.md`. It writes non-assembly replacements to `build/label-apply-report.txt` for review. |
| `fingerprint.ts <repo>` | Assembles each entry point and prints image hashes and symbol tables as JSON. It must run from inside `tools/` so the `atom-z80` import map applies, which `verify.ts` arranges. |
| `verify.ts <repo> <baseline.json> <maps-dir>` | Reassembles the entry points. It requires byte-identical images and checks that every baseline global (as renamed) keeps its value. |
| `example-strings-map.json` | The pilot map for the string runtime, kept as a model of the expected style |

A map file looks like `tools/labels/example-strings-map.json`:

```json
{
  "globals": { "SRTSACL": "STR_NEW", "SRTSSZ": ".SIZE" },
  "privates": { "SRTSVLD": { ".L1": ".BAD" } }
}
```

`globals` maps an old global to a new global name, or to a `.name` to demote
it. `privates` renames existing private labels, keyed by the old name of the
global label that owns them. Always map old names: maps stay cumulative, and
the tools reapply them from the baseline names.

`apply.ts` rewrites the files in place. Apply each batch's map once, then keep
it in `maps/` so that `verify.ts` knows the full old-to-new relation.

## Procedure

### 0. Prepare the tooling and baseline

1. Check the entry points. `demote.ts` exports `ENTRIES`, and
   `fingerprint.ts` lists the same entries. At the time of writing these
   are `src/runtime/image.asm`, `src/compiler/scope/compiler.asm` and
   `tests/cpm-effects.asm`, which pulls in the otherwise orphaned
   `src/runtime/external-effects.asm`. After the refactor, confirm that
   these entries still reach every `.asm` file under `src/`.
2. Before renaming anything, generate the baseline:

   ```bash
   cp tools/labels/fingerprint.ts tools/.fingerprint.ts
   deno run --config deno.runtime.json -A tools/.fingerprint.ts $PWD > tools/labels/baseline.json
   rm tools/.fingerprint.ts
   ```

   Then run `verify.ts $PWD tools/labels/baseline.json tools/labels/maps`
   with an empty `maps/`. It must print `VERIFIED`.
3. Fix comment alignment in `apply.ts`. When a replacement changes a name's
   length, pad or trim the whitespace before a trailing `;` comment so the
   comment stays in its original column, or at least one space after the code.
   Apply the example strings map, if its labels still exist, to confirm that
   comments line up.
4. In `apply.ts`, reject a new global name that already exists unrenamed
   elsewhere in the image, and two old names that map to the same new name
   within one image. A clear message beats a raw ATOM duplicate error.
5. Run `deno fmt tools/labels` and `deno lint tools/labels` so that
   `deno task check` stays green.
6. Commit the tooling and baseline: `Add label rename tooling`. Running
   deno can modify `deno.lock`; restore it rather than committing that
   change.

### 1. Rename in batches

Work through the batches in the table below, one area per batch. Within a
batch:

1. Run `deno run -A tools/labels/perfile.ts $PWD` and `demote.ts` to see the
   batch's kept and demotable labels.
2. Read every file in the batch fully. The header comment on each routine is
   the main source of meaning. Read callers in other files for globals that
   cross areas.
3. Write `tools/labels/maps/<image>-<area>.json`. Every label defined in the
   batch's files gets an entry: globals, demotions and any existing privates
   that should be renamed (for example `.L1`).
4. `apply.ts --dry`, then `apply.ts`. Read `build/label-apply-report.txt`.
   Every non-assembly replacement must be a label lookup or a code mention in
   documentation.
5. Run `verify.ts $PWD tools/labels/baseline.json tools/labels/maps`. It must print `VERIFIED`. If ATOM reports a duplicate
   name, rename to resolve it. Never accept an image that is not identical.
6. Read `git diff` for the batch as prose. If a name still needs its comment
   to decode it, choose a better name.
7. Commit the batch, for example `Rename vector runtime labels`. Each commit
   must assemble identically on its own.

Do runtime batches before compiler batches, because the compiler mirrors
runtime names through `values.inc`. Do batch G last:

1. Edit the left-hand names (and the `SRTIMAGE` and `SRTIEND` labels in
   `template.inc`) in `generate-scope-runtime.ts`. The runtime names on the
   right-hand side were already renamed by the earlier batches through
   `apply.ts`.
2. Run the generator: `deno run --config deno.runtime.json -A
   tools/compiler-checks/generate-scope-runtime.ts`.
3. Confirm that `src/runtime/values.inc` and `template.inc` match what
   `apply.ts` produced, then run `verify.ts`.

Equates (`NAME EQU ...`), for example in `storage/cell-contract.asm` and
`command/driver.asm`, follow the same convention. Use the area prefix for
area-specific constants and a bare name for image-wide constants such as
`CELL_SZ`.

Independent batches may be named in parallel, one per area, because the
prefixes keep them apart. Apply and verify them one at a time.

### 2. Finish

1. Run `demote.ts` again. It should report no demotable globals, apart from
   ones the batch notes chose to keep, which should be listed there.
2. Run `grep -rnE '\b(SRT|SC)[A-Z0-9]{2,6}\b' src tools tests docs`. Only
   intentional matches may remain.
3. Rewrite the ownership paragraph in `docs/codebase.md`, which currently
   reads "`SC` is the scope compiler, `RT` is the runtime ...", so that it
   describes the new convention and points to the area tables. Move the
   convention section of this plan into a permanent `docs/labels.md`, then
   delete this plan.
4. Run the full test suite: `deno task test`, then `deno task test:cpm`. The
   images are byte-identical, so failures can only come from a missed name in
   a script. Fix them in the script, never in the assembly.
5. Remove `tools/labels/baseline.json` and the maps, or keep them with a
   note, as the user prefers. The scanner and verifier are worth keeping for
   future renames.

## Acceptance criteria

- `verify.ts` prints `VERIFIED` against the step-0 baseline on every commit.
- `deno task test` and `deno task test:cpm` pass.
- No global keeps an `SRT` or `SC` image prefix.
- Every global that `demote.ts` can demote is either private or listed with a
  reason.
- A reviewer reading any routine can tell from its label names what each
  label is, without decoding them from the comments.

## Open decision

ATOM ignores case, so labels could be written in lower case (`str_copy`,
`.len_read`) with upper-case instructions, making names stand out from
mnemonics. The plan uses upper case for consistency. Converting is a
mechanical pass with the same tooling and can be done later; ask the user
before starting batch R1.

## Pilot

`example-strings-map.json` renamed the string runtime (43 labels, 22 of them
demoted) and passed `verify.ts` against `main` at `a596f2e`. Those edits were
then reverted, so the map is a style reference. Reapply it as batch R0 if
the labels are unchanged. Examples:

| --- | --- | --- |
